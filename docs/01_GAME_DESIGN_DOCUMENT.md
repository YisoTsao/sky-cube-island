## 1. 產品定位

### 1.1 一句話賣點

在**像精工微縮模型一樣精緻**的立體漂浮群島上，玩家像一位天空築城師，運用**高低差、橋梁瓶頸、地形重塑與防禦塔位置**，把入侵怪物引到自己設下的防線，守護天空之心。

### 1.2 三個設計支柱

1. **地形就是戰術**：地面不是背景；每一次合法編輯都能明顯改變敵人路線、塔的部署位置或可攻擊角度。
2. **桌上微縮模型的精緻感（Diorama Fidelity）**：明亮、方塊化、手工感；每一塊地都有倒角、色階與光影層次，每一次操作都有份量十足的回饋。精緻來自**光影、材質細節、動畫手感與一致的調色盤**，不是面數；避免 Minecraft 採礦觀感。
3. **清楚而能重玩**：玩家可預覽敵人路徑、塔射程與遮擋、資源消耗，逐步學會「為什麼輸、下次怎麼改」；波次回顧把失誤具體指出來。

### 1.3 目標使用者與平台

- 主要：喜愛塔防、解法優化、地形策略與精緻 3D 美術的 PC 玩家。
- 操作：滑鼠＋鍵盤，單人離線。Web Demo 支援桌面瀏覽器（WebGL2），手機不是 MVP 驗收目標。
- 解析度：1080p 為基準，**1440p／4K／Retina（DPR 2）須保持銳利**；UI 與圖示一律向量或高解析素材。
- 初步定價假設：Steam 買斷 **US$6.99～9.99**；不是已驗證定價，須依內容量與玩家回饋調整。

### 1.4 明確不做

無限世界、逐格挖礦、角色直接砍怪、自由飛行建橋、多人、季票、課金、AI NPC 聊天、真實流體物理、動態可破壞全部橋梁、寫實照片材質、重度景深遮蓋戰場。

## 2. 世界觀與視覺方向

天空群島依靠「天空之心」懸浮於雲海之上。虛空裂縫在各座島嶼上開出傳送門，魔物沿著原有道路、斜橋與階梯前進。玩家是「天空築城師」，能短暫調節部分土地的高度，重新安排防禦建築，將入侵者擋在核心之外。

- **視覺關鍵字**：**Hi-Fi Voxel Diorama**——方塊輪廓＋柔和全域光＋手工上色感。像放在桌上的精緻模型，從雲海中浮起。
- **畫面層次**（由近到遠）：戰術層（路線、射程、選格）→ 戰場島嶼 → 島底岩根與瀑布 → 雲海 → 遠方剪影島 → 漸層天空。
- **地圖辨識**：平台頂面草綠、崖壁土層／岩灰分層、橋梁木色、合法路線淡金色、核心晶藍；前景不遮住戰術資訊。
- **敘事**：每章一張插畫與簡短文字。第一個 Demo 無語音、無複雜對話樹；關卡開場用 4～6 秒可跳過的鏡頭巡禮交代地形。
- **參考邊界**：可以參考圖片中的立體平台構圖，禁止直接複製既有作品特定造型、角色或關卡配置。

## 3. 遊戲核心循環與狀態

```text
選擇關卡
  ↓
開場鏡頭巡禮（可跳過）：2 個入口／3×3 核心／高低平台／橋梁
  ↓
PREPARE：查看波次預告 → 升降可編輯地形 → 放塔／路障（可撤銷）
  ↓
即時預覽兩條有效路線（含幽靈試走）、射程及地形遮擋
  ↓
START WAVE → COMBAT：怪物跨橋與階梯進攻，塔自動索敵
  ↓
波次完成 → 波次回顧（傷害、漏怪位置）→ 領取獎勵 → 下一輪 PREPARE
  ↓
五波通關 / 天空之心歸零失敗 → 評星、失敗分析、重試
```

| 狀態 | 可以做 | 不可以做 |
|---|---|---|
| `MENU` | 選關、載入、設定 | 編輯戰場 |
| `PREPARE` | 改地形、放／升／售塔、放／拆路障、**撤銷**、預覽路徑、看波次預告 | 怪物移動與射擊 |
| `COMBAT` | 旋轉相機、暫停、看路線／射程、1×／2× | **改地形、建塔、賣塔、拆橋、撤銷** |
| `WAVE_RESULT` | 領取已結算獎勵、檢視波次回顧 | 重複領獎 |
| `VICTORY`/`DEFEAT` | 讀取結算、失敗分析、重玩、回選單 | 修改已完成的戰局 |

`PAUSED` 是 Runtime 的暫停旗標，**不覆寫上一個 GamePhase**。一波所有排程怪物已生成，且場上沒有存活怪物，才算結束。

## 4. 世界座標、地圖與平台

### 4.1 地圖規格

| 參數 | 規則 |
|---|---|
| `width` / `depth` | MVP **32 / 32**；可配置，禁止寫死 |
| X/Z | 水平整數格，x、z ∈ [0,31]，每格 1 world unit |
| Y | `elevation × 0.5` world unit，Y-up |
| `elevation` | 0～6，整數；不同平台可位於不同高度 |
| 空白區域 | 沒有地面節點，即虛空；不是可放塔地塊 |
| 島嶼構成 | 多個 `Platform`，每個有一群地格；可以有不規則邊界 |
| 多層座標 | 地格唯一識別使用 `cellId`；保留同一 X/Z 有不同平台／高度的擴充能力 |
| 地圖頂面 | 地形邏輯只看資料節點，不從視覺 Mesh 推算 |

MVP 使用三個主要高度平台（低、中、高），以及至少兩段專用連接通道。**不要求玩家自由建造跨空隙橋梁**。地形修改只在指定 `editable` 地格進行。

### 4.2 連接型態

| 元件 | 是否可走 | 是否可放塔 | MVP 可否修改／摧毀 | 用途 |
|---|---|---|---|---|
| 平台草地／石地 | 是，依阻擋狀態 | 可建造區域才可 | 可編輯區才可 | 基本戰場 |
| 虛空／懸崖外側 | 否 | 否 | 否 | 製造平台分離 |
| `BRIDGE` 木橋 | 是，只走橋面節點 | 否 | **否** | 懸空跨平台 |
| `STAIR` 階梯 | 是，按節點逐級前進 | 否 | **否** | 連接不同高度 |
| `RAMP` 坡道／斜橋 | 是，沿配置的節點鏈前進 | 否 | **否** | 懸空且變高的連接 |
| `WALL` 路障 | 否 | 否 | 可在準備階段拆裝 | 改變地面路線 |
| `CORE` 3×3 | 核心內部不可走 | 否 | 否 | 玩家防守目標 |
| `PORTAL` | 可走 | 否 | 否 | 敵人來源 |

**重要**：兩個平台即使在畫面上看起來很接近，只有導航資料明確標記可連接，怪物才可跨越；絕不因模型距離近就跳崖。橋面、樓梯與坡道必須由**實體導航節點鏈**表示，不可使用「一端瞬間傳送到另一端」的尋路捷徑。

### 4.3 怪物通行與核心抵達

- 地面怪只可走四方向合法相鄰節點，不走對角、不自由跳躍或飛行。
- 同平台普通節點，兩格相鄰且高度差 ≤1 才能步行；大於 1 是斷崖。
- 不同平台或橋／階梯連接必須依 Connector 的**指定節點順序**行走。
- 通道中每個相鄰步驟的平面距離為 1 格，高度差 ≤1 級。
- 防禦塔與路障占用的格子不可走；水與虛空不可走。
- 核心 **占 3×3 格且不可進入**；在其四周定義至少 2 個不可編輯的 `coreApproachNodeIds`，**敵人抵達任一合法 Approach 節點**即造成核心傷害並離場。
- 多入口時，每個 Portal 都必須至少可到達一個 Approach 節點，且非僅在某一種未來配置下可達。
- 第一版不允許拆除關鍵橋；預留後續「可破壞橋樑」的規則（T2），但不是 MVP。

### 4.4 地形編輯範圍

- 只允許 `PREPARE`，地圖內指定 `editable=true` 的**普通平台地格**。
- `RAISE`：+1 級、花 12 金幣、上限 6；`LOWER`：−1 級、花 8 金幣、下限 0。
- `PLACE_WALL`：15 金幣；`REMOVE_WALL`：退還 ⌊15×0.5⌋＝7 金幣。
- 不可編輯：核心、入口、橋／坡道／階梯及其端點保護區、塔占用格、永久裝飾與不可編輯區。
- 高低變化如果會改變普通平台內的坡度／斷崖，必須重算路線；**不得修改任何 Connector 端點的高度或位置**。
- 地形升降可以形成可通行的逐級坡面，也可能形成不可跨越的 2 級以上落差。
- 操作必須「預覽 → 驗證 → 提交」。不合法時**不改狀態、不扣錢**，以文字與格子顏色回饋原因。
- MVP 採用**固定地形外圍**與指定編輯區，不允許玩家向虛空加蓋地塊，避免變成自由建造沙盒。
- 🆕 **可編輯格的視覺標記**：可編輯地格頂面有細微的符文刻紋與淡金邊（Medium 以上另有緩慢呼吸光），在任何畫質與相機角度都能一眼分辨；這是戰術資訊，不是裝飾。

### 4.5 防禦塔占地與放置

- 一般塔固定 **2×2**，一次占用 4 個普通地格；塔 Anchor 是左上角最小 x/z；不得跨平台、跨橋或超出島邊。
- 四格需為同一平台、同一高度、皆可建塔、未占用；不能與入口／核心／Connector 保護區重疊。
- 放置後這 4 格均視為阻擋地面怪物；必須驗證**所有入口**仍可抵達核心。
- 塔設計以 2×2 格外形為主要尺寸；影響選取、射程圈中心、碰撞及模型比例。特殊 1×1 陷阱留給正式版（T2）。
- `towerAnchor` 對應 footprint 4 格；塔出售後會釋放全部 footprint。

### 4.6 關卡路徑上限

MVP 預設 `maxShortestPathCost=160`（每步成本 1），**每個入口**皆需通過可達與上限驗證，避免玩家惡意封繞成無限長路。此值只是 32×32 多平台首輪測試參數，需依地圖及玩家測試校正；不可沿用舊版 16×16 的「48 格」限制。

## 5. 高低差、視線與防守策略

### 5.1 射程規則（MVP）

採用**世界空間 3D 距離**而非只量水平距離。塔射擊原點是邏輯定義的炮口高度，敵人使用邏輯定義的瞄準中心高度；兩者由資料定義（初值見 §7、§8），不從任意 GLB 骨架猜測。

- `range = baseRange + levelRangeBonus + 0.3 × clamp(towerElevation − enemyElevation, 0, 3)`。
- `distance = sqrt((dx)^2 + (dy)^2 + (dz)^2)`，以 world units 計算。
- 必須**同時滿足 `distance <= range` 與 `hasLineOfSight == true`** 才能攻擊。
- LOS 由固定的戰術遮擋資料判斷：實心山壁、比射線高的地面、指定的不透明路障；不能穿越岩壁射擊。
- 木橋欄杆、雲朵、草叢、純裝飾物**不**阻擋射擊；可避免美術與判定不一致。
- 顯示選塔射程圈與「被地形遮擋」提示，不能只畫一個平面圓宣稱所有敵人可命中。
- 🆕 **射程視覺化**：射程以「貼地投影」呈現——光環沿地形起伏貼合各層平台表面，可攻擊區域為實色，被岩壁遮擋的區域以斜線陰影顯示，並在遮擋邊界畫出細亮線。高地加成部分以較淡的外環顯示，讓玩家看出「站高多打多遠」。

### 5.2 三種主要戰術

1. **高台狙擊**：在高處架箭塔，以射程與良好視線優勢提前攻擊。
2. **橋口攔截**：在固定橋梁附近設冰晶塔與砲塔，利用敵人必須經橋的瓶頸。
3. **地形改路**：在可編輯普通地格升降或放路障，讓敵人在高台火力範圍中走更久，但不可完全封死路線。

**設計風險**：若所有塔都能無視山壁攻擊，立體平台會淪為純裝飾；若視線過度嚴苛，玩家可能不了解為何塔不開火。必須做可視化與可理解的回饋：🆕 塔因 LOS 被擋而無法攻擊射程內敵人時，塔頂顯示小型「眼睛＋斜線」圖示，選取時列出原因。

## 6. 經濟系統

MVP 只有 **Gold** 一種局內資源，不引入能量、木材、礦石等多貨幣。

| 事件 | 金幣變動 |
|---|---:|
| 初始資金 | 220 |
| 升地／降地 | −12／−8 |
| 放路障／拆路障 | −15／+7 |
| 擊殺史萊姆／疾風獸／石殼巨人 | +6／+8／+12 |
| 每波清波 | +35／+40／+45／+50／+70 |
| 出售塔 | 退回 **⌊已投入成本 × 0.65⌋** |
| 🆕 撤銷本次準備期內的操作 | **全額回到操作前**（見 §6.1） |

- 初始天空之心 HP = **20**；金幣永遠不得負數。
- 怪物到達核心不給擊殺金幣；敵人死亡不扣核心 HP。
- 獎勵只在波次完成時結算一次，禁止讀檔重複領取。
- 經濟是第一版平衡草案，實際須以模擬與實玩測試調整。

### 6.1 🆕 準備期撤銷（Undo，T0）

- **目的**：減少誤點挫折，鼓勵玩家「試一下這樣改」，強化支柱 1、3。
- 只在 `PREPARE` 可用；只能撤銷**本次 PREPARE 期間**成功提交的操作，依序回退，最多 20 步。
- 撤銷把戰局恢復為該操作之前的完整狀態，因此金幣、地形、塔、路障、路線**全部回到原樣**（等於全額退款）。
- `START_WAVE` 後撤銷紀錄清空；讀檔後也不保留撤銷紀錄。COMBAT 中不可撤銷。
- 與「出售」的差異：出售上一波以前建的塔只退 65%；撤銷只對本準備期內的操作有效，不構成漏洞（準備期內沒有任何隨機性或時間收益）。

## 11. 美術、光影、特效與表現規格

> 完整美術聖經另存 `docs/ART_BIBLE.md`（P1 建立）；本節是**必須遵守的規則摘要**，與技術文件 §9 一一對應。

### 11.1 ART BIBLE：Hi-Fi Voxel Diorama

**一句話**：精緻，來自「每一塊方塊都被照顧過」，而不是更多面數。

- **雙尺度體素**：
  - **地形尺度**：1 格＝1 world unit，高度階 0.5；地形是程序化生成。
  - **美術微體素**：塔、怪、核心、橋、道具以 **1/16 格**（每格 16 個微體素）製作；細節小道具最細可到 1/32。這是「高清 Voxel」的核心——近看有細節，遠看是乾淨方塊。
- **倒角與邊緣**：所有方塊外露邊有細微倒角／邊緣高光，頂面邊緣略亮、底邊略暗；不使用全黑描邊。
- **色彩層次**：同一材質至少 3 階色（亮／中／暗）並對每塊方塊做 ±4% 明度隨機擾動，避免大片死色；崖壁依高度呈土層條紋，頂部草皮略微懸垂出崖邊。
- **單一主調色盤**：全專案美術資產共用一張主調色盤（約 64～128 色），由 ART_BIBLE 管控；新資產不得自創色票。這同時確保風格統一與渲染效能（共用材質）。
- **形狀語言**：友方建築＝方正、穩重、暖色木石＋藍晶；敵人＝圓潤或尖銳的有機剪影、高飽和異色（綠、橙、紫灰）；核心＝唯一的正八面體晶體，全場最亮的藍。
- **尺寸**：怪物視覺高約 0.5～0.9 格；塔約 1.5～2.2 格高；炮口與瞄準高度須對齊 §7、§8 的邏輯值。
- **攝影機**：Orthographic，俯視 35°～45°，Q/E 旋轉 90°（0.35s 緩動過渡）、滑鼠縮放（3 段吸附＋平滑）；場景可適度平移。
- **禁止事項**：照片寫實貼圖、高頻雜訊貼圖、過度 Bloom 糊光、重度景深遮住戰場、全畫面濾鏡讓路線色失真、與調色盤無關的螢光色。

### 11.3 後處理與「可讀性鐵律」

- **後處理堆疊**（High 為準）：抗鋸齒 → 螢幕空間 AO → 選擇性 Bloom（只對自發光） → 色彩分級（LUT，每章一組） → 極輕暗角。
- **微縮模型感（Tilt-shift）**：只在開場鏡頭、選單背景與拍照模式啟用，**戰鬥與準備期預設關閉**。
- **可讀性鐵律**：路線、射程、合法／非法格、選取外框、波次預告、血條等**戰術層**一律在後處理之後繪製，不吃 Bloom、不被色彩分級改色、不被暗角壓暗；被地形擋住的路線段以虛線「透視」顯示。
- 任何新特效若在 Low 畫質或色盲模式下讓戰術資訊變難辨識，一律退回修改。

| 清波／勝利 | 金色粒子從核心上升、星級逐顆落下彈跳 | T0 |
| 幽靈試走 | PREPARE 時沿每條路線循環播放半透明「幽靈史萊姆」小隊，讓路線長短一目了然 | T0 |
| 鏡頭 | Q/E 旋轉緩動、縮放平滑、開場巡禮、勝利環繞 | T0 |
| 環境動態 | 草叢與樹隨風擺動、橋繩微擺、雲海流動 | T0（Low 可關） |

**手感原則**：回饋要「快、短、有重量」——操作後 50ms 內必有視覺回應；單一動畫不超過 0.6s，不阻擋玩家下一個操作。

### 11.5 VFX 清單

| 類別 | 必備特效 |
|---|---|
| 攻擊 | 箭矢拖尾、冰稜、砲彈弧線與煙跡 |
| 命中 | 木屑、冰霜、爆炸火球＋方塊碎石、物理減傷火花 |
| 狀態 | 減速結霜光暈、敵人血條、LOS 被擋圖示 |
| 地形 | 升降塵土與石屑、可編輯格呼吸光、路障落地震波 |
| 目標 | 核心旋轉光芒與裂痕、傳送門漩渦、開波脈衝 |
| 環境 | 雲海、高度霧、草葉、晶礦微光 |

- 粒子以**小方塊**為主要形狀（不用圓形柔光點），維持 Voxel 一致性；煙與霧可用柔邊貼片。
- 同時存在的特效有數量上限，超過時淘汰最舊者；Low 畫質減量但不移除任何「傳達規則」的特效（如減速光暈）。

### 11.6 Golden Shot 驗收清單（視覺 DoD）

在 High 畫質、1080p、L1-01、固定相機角度下截圖，必須全部通過：

1. 第一眼（3 秒內）能指出：兩個入口、核心、兩條橋、可編輯格。
2. 三層平台的高低關係清楚，不需數字提示即可看出誰高誰低。
3. 每塊平台都有明顯的島底岩根與雲霧，畫面有「懸浮」而非「放在地上」的感覺。
4. 畫面中沒有任何大片單一死色；崖壁有土層、頂面有色階。
5. 陰影柔和且方向一致，沒有鋸齒、漏光或陰影痤瘡（shadow acne）。
6. Bloom 只出現在核心、冰晶、傳送門、晶礦。
7. 4K／DPR 2 截圖中方塊邊緣與 UI 文字銳利，沒有模糊放大感。
8. Low 畫質截圖中，第 1 項的戰術資訊依然全部可辨識。

### 12.1 🆕 UI 美術與動態

- **主題**：淺木框＋拋光晶石鑲邊＋羊皮紙底，與場景調色盤一致；面板有柔和投影，懸浮於畫面之上但不遮戰場重點。
- **字型**：中文使用清晰的黑體（如 Noto Sans TC）做內文，標題用具手工感的展示字型；Web 版做字型子集化以控制下載量。
- **動態**：按鈕有懸停放大 1.04×、按下下沉；數值變化以滾動數字呈現；面板開關 0.15～0.2s 緩動；新解鎖的塔按鈕有一次性光芒。
- **清晰度**：所有圖示為向量；UI 依視窗與 DPR 縮放，4K 下保持銳利；提供 UI 縮放 80%～150%。

### 12.3 🆕 音訊方向

- **風格**：輕快的木管、撥弦與鐘琴，配合空氣感的弦樂墊底；「天空、微縮、手工」的感覺。
- **自適應音樂（T0）**：同一首曲子分兩層——PREPARE 只有輕柔的主旋律層；COMBAT 疊上打擊與低音層並平滑交叉淡入；核心 HP ≤4 時加入緊張層。清波、勝利、失敗各有短促音樂片段。
- **音效清單（T0）**：建塔組裝、升級卡榫、出售金幣、升地石磨、降地沉降、路障落地、非法操作、各塔開火與命中、敵人移動（每種一組）、敵人死亡、核心受擊、開波號角、清波、勝利、失敗、UI 點擊與懸停、環境風聲與鳥鳴。
- **混音規則**：大量同類音效有同時播放上限並隨機微調音高（±5%）避免機械感；核心受擊時其他音效短暫壓低；依畫面左右位置做聲像偏移。
- 所有音效與音樂登記來源與商用授權。

## 13. 存檔、成績與商業驗證

- 自動存檔：進入 **PREPARE**、PREPARE 中每次成功操作後（節流）、**WAVE_RESULT** 時儲存完整資料；COMBAT 不存，避免戰鬥途中狀態一致性問題。撤銷紀錄不存檔。
- 存檔紀錄：關卡 ID、已完成波次、金錢、核心 HP、地形差異、塔／牆、遊戲版本、已領獎列表。排行榜與登入非 MVP。
- 🆕 設定（畫質、音量、無障礙）與戰局存檔**分開儲存**，清除戰局不影響設定。
- 商業方式：單人 Demo 免費試玩，正式版買斷；僅在玩家有明確興趣後新增章節與 DLC。
- 🆕 商店素材：Golden Shot 與拍照模式（T1）截圖直接作為 Steam／社群宣傳圖，因此美術品質就是行銷投資。
- 遊玩測試：至少找 15～20 位非開發者；觀察是否會主動修改地形、能否理解橋與斷崖的路線限制、能否用高地改善防守。
- 初步通過門檻（目標，不是預測）：≥70% 能在無提醒下理解路線預覽；≥60% 可完成前三波；≥70% 失敗者可描述原因。
- 🆕 視覺與手感門檻：≥80% 能在 10 秒內指出可編輯地格；≥70% 在問卷中以「精緻／好看」形容畫面；≥60% 主動使用過撤銷或幽靈試走。

> P1 的 Golden Shot 是**限時樣板**（建議 ≤3 個工作天），目的在早期鎖定光影與材質方向；不會違反「先邏輯、後大量模型」的原則——大量資產製作仍在 P4～P5。

### MVP Definition of Done

1. 真正的 **32×32 多平台**地圖與 0～6 高度可讀，不是只放單塊平面島。
2. 至少三個高度平台、兩條 Connector，跨平台只走合法節點；不穿崖、不瞬移。
3. 核心 3×3、塔 2×2、兩入口；建造和路障能準確檢查所有 footprint。
4. 任意合法地形更改後，所有入口到任一核心 Approach 仍可到達；拒絕操作不扣金；撤銷能完全還原。
5. 3D 射程加 LOS 有一致的邏輯與可視化，地形確實影響戰鬥。
6. 三塔、三怪、五波、升級、出售、勝敗、存檔、波次預告與回顧都能正常運作。
7. 戰鬥為可重現的固定 tick；重要規則有自動化測試。
8. 在指定桌面測試機器以 **High 畫質、1080p、60 FPS 為優化目標**，用實測 Profile 記錄，不宣稱所有裝置皆達標；Low 畫質在入門內顯測試機可玩。
9. 🆕 §11.6 Golden Shot 驗收清單全部通過；§12.2 無障礙設定全部可用。
10. 模型／音效有資產來源與商用授權紀錄；初版不依賴即時 AI API。
