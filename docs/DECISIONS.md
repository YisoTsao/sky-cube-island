# 實作決策紀錄（DECISIONS）

本文件記錄實作 v2.1 GDD／技術架構時，文件未明確規定或刻意偏離之處。

| # | 決策 | 理由 |
|---|------|------|
| D-01 | 不使用 R3F，改用 `SceneApp` 類別管理的純命令式 Three.js | 每幀數百實體與後處理管線，用命令式較好控制 draw call 與 GC；React 只負責低頻 HUD（符合 Tech §8.2 精神）。 |
| D-02 | 新增 `CONTINUE` 指令（WAVE_RESULT → PREPARE） | 文件有結算畫面但未定義離開的指令；維持「所有狀態轉移都是指令」。 |
| D-03 | 新增拒絕碼 `MAX_LEVEL` | 升級已滿級塔需要明確回饋。 |
| D-04 | `GameState` 新增 `builtWave`、`spawnQueue`、`frozenRoutes` | 分別用於統計、確定性出怪、戰鬥中凍結路線（存檔可完整還原）。 |
| D-05 | 視線（LOS）只看地形柱頂，木牆與橋面不遮擋 | 讓牆的用途單純是「改路」，避免玩家誤以為擋視線；Amanatides–Woo 2D 精確格走訪。 |
| D-06 | 核心周圍一圈為保護區 | 避免把塔直接堆在核心旁或封死最後一段路。 |
| D-07 | 太陽方向為畫面左上偏向鏡頭 | 等角視角下島嶼側面有明暗對比、陰影落在右後方不遮擋路線。 |
| D-08 | 開場運鏡用正交鏡頭環繞＋移軸（tilt-shift），不切透視鏡頭 | 與遊戲視角一致、沒有切換跳動，移軸提供「模型島」質感。 |
| D-09 | 調色以自製 GradeEffect 取代 LUT 檔 | 不需外部資產，參數可依畫質調整。 |
| D-10 | 音效、音樂全部 Web Audio 程序合成（已由 D-19 部分取代） | 零授權風險、零下載；每次播放 ±5% 音高、±2 dB 變化避免重複感。 |
| D-11 | 可改造地塊的符文格線依情境顯示（戰鬥 0、待機 0.3、拿地形工具時 1） | 常駐全亮會讓畫面很雜，玩家需要時才強調。 |
| D-12 | 數值平衡維持文件原值 | 自動測試的貪婪機器人能無漏怪通關 5 波，代表偏簡單；待實際試玩後再調整。 |
| D-13 | 低畫質使用 BasicShadowMap，其他使用 PCF（three r18x 已移除 PCFSoft） | 相容新版 three。 |
| D-14 | N8AO 一律全解析度（「高」用 8 取樣、「極致」16 取樣） | n8ao 2.0.1 的半解析度路徑使用 MRT render target，與 three r18x 不相容會丟錯；改以降低取樣數控制成本。 |
| D-15 | 取代 D-12：L1-01 改為長波次、多怪物（v2.2） | 試玩回饋「太簡單、太短」。每波出怪至少持續 120 秒（兩個入口都是），每波 90–200 隻，並新增 `WaveDef.hpScale`（1.0 → 1.8）讓後段更硬。由 `tests/integration/balance-bot.test.ts` 的機器人鎖住：積極再投資的機器人能贏但會掉血，只在準備期花錢或留著金幣不用的機器人會輸。 |
| D-16 | 新增 5 種怪物：小果凍、分裂史萊姆、鐵甲甲蟲、癒光精靈、岩王巨像 | 大量怪物需要不同解法：成群（砲塔）、分裂（持續火力）、物抗 50%（冰晶塔魔法）、治療光環（優先擊倒）、Boss（緩速減半）。治療量為固定值 × hpScale，避免以百分比治療 Boss 造成無法擊殺。 |
| D-17 | 戰鬥中可建塔、升級、出售（地形與木牆仍限準備期） | 兩分鐘以上的波次若只能在波次之間花錢，擊殺金幣會閒置。戰鬥中新塔不可蓋在已凍結的敵人路線上（拒絕碼 `ON_ACTIVE_ROUTE`），並照常檢查下一波仍有路可走。 |
| D-18 | 冰晶塔基礎傷害 8 → 16、起始金幣 220 → 300，擊殺金幣下調 | 冰晶塔成為對付鐵甲甲蟲的魔法主力；大量怪物時以數量帶來收入，單隻獎勵降低以免經濟失控。 |
| D-19 | 取代 D-10：背景音樂與主要音效改用 CC0 錄音素材（cynicmusic、Kenney、Beatscribe） | 試玩回饋希望音樂更好聽。只採用 CC0 素材，來源逐一登記於 `public/audio/CREDITS.md`。素材在第一次點擊後才延遲載入（約 3 MB），載入前或失敗時自動退回原本的程序合成，因此離線開啟 dist/ 仍有聲音。核心 HP ≤4 的緊張層改為戰鬥曲加速 7%。 |
